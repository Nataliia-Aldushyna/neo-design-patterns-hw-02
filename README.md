# SOLID Notification System (TypeScript)

## Домашнє завдання до теми: Принципи проєктування SOLID

## 📌 Опис завдання

У цьому завданні було виконано рефакторинг навмисно погано спроєктованої системи повідомлень.

Початковий код містив жорсткі залежності між класами, порушення принципів SOLID та відсутність абстракцій. Основною метою роботи було перебудувати архітектуру системи так, щоб вона стала масштабованою, гнучкою та відповідала принципам чистого коду.

---

## 🎯 Мета роботи

Реалізувати систему повідомлень, у якій:

- кожен канал повідомлень є окремим класом
- логіка відправки повідомлень відокремлена від бізнес-логіки
- залежності передаються через абстракції (Dependency Injection)
- система легко розширюється без зміни існуючого коду
- дотримано всі принципи SOLID

---

## 🏗 Реалізована функціональність

Система підтримує відправку повідомлень через різні канали:

- Email повідомлення
- SMS повідомлення
- Push повідомлення

Кожен канал реалізований як окремий сервіс, що використовує спільний інтерфейс.

Також реалізовано:
- централізований сервіс логування
- сервіс оркестрації повідомлень
- користувача, який більше не залежить від логіки відправки повідомлень

---

## 🧠 Застосовані принципи SOLID

### ✔ Single Responsibility Principle (SRP)
Кожен клас має одну відповідальність:
- `User` — зберігання даних користувача
- `Logger` — логування
- `NotificationService` — координація відправки повідомлень
- `EmailNotification`, `SMSNotification`, `PushNotification` — окремі канали доставки

---

### ✔ Open/Closed Principle (OCP)
Система відкрита для розширення:
- можна додавати нові канали (наприклад, Telegram)
- без зміни існуючого коду

---

### ✔ Liskov Substitution Principle (LSP)
- усі канали повідомлень взаємозамінні
- будь-який канал можна передати в `NotificationService` через спільний інтерфейс

---

### ✔ Interface Segregation Principle (ISP)
- інтерфейси розділені на вузькі та спеціалізовані
- класи реалізують тільки необхідні методи

---

### ✔ Dependency Inversion Principle (DIP)
- високорівневі модулі не залежать від конкретних реалізацій
- залежності передаються через абстракції (constructor injection)
- `Logger` та канали повідомлень інжектяться як залежності

Встановити залежності:

```bash

```

Запустити проєкт:

```bash
npx ts-node src/main.ts
```
